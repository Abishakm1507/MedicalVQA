# FS‑002 Implementation Report

**Feature Specification:** FS‑002 – Candidate Region Localization

## 1. Overview
Implemented a modular region‑localization architecture on branch `feat/phase-1-data-localization`.

- **BaseRegionDetector** – abstract interface defining `detect(image: Image) -> List[CandidateBox]`.
- **MockRegionDetector** – deterministic synthetic detector for unit‑tests and fast prototyping.
- **FasterRCNNRegionDetector** – Torchvision Faster‑RCNN adapter with CPU‑only weights (randomly initialized).  No COCO pretrained weights are downloaded; a warning is logged if the user attempts to load them.
- **Pre‑processing** – modality‑aware DICOM handling (CXR vs CT) documented in ADR 0006.
- **Post‑processing** – score filtering, NMS, and candidate‑box building with strict boundary validation.

## 3. Key Design Decisions
| Decision | Rationale |
|---|---|
| **CPU‑only** | Aligns with hardware constraints (Intel i5, no CUDA). |
| **No synthetic boxes** | Enforces research integrity – empty detections return `R = ∅`. |
| **Modality‑aware DICOM** | Prevents misuse of Hounsfield‑Unit conversion on chest X‑rays (ADR 0006). |
| **Configurable `max_k`** | Upper‑bound of 7 candidate boxes matches paper’s experimental setup. |
